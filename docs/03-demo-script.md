## คำถามที่อาจารย์น่าจะถาม + คำตอบ

**Q: เป็น IoT แต่ไม่มีฮาร์ดแวร์จริง?**
A: ฝั่งอุปกรณ์มี 2 แบบ: Simulator ที่จำลองฟิสิกส์ของเครื่องจักร (อุณหภูมิ, ค่าสั่นตาม ISO 10816, ยอดผลิต) และ **ESP32 บน Wokwi** ที่รันเฟิร์มแวร์จริง ต่อ WiFi และ MQTT จริงผ่านอินเทอร์เน็ต เปลี่ยนเป็นบอร์ดจริงได้โดยไม่ต้องแก้โค้ดฝั่ง Server เพราะใช้ topic และ JSON format เดียวกัน

**Q: Predictive คำนวณยังไง?**
A: เก็บค่าสั่น 10 ค่าล่าสุดของแต่ละเครื่อง ทำ Linear regression หาความชัน ถ้าค่าเกิน 4.5 mm/s (เริ่มโซน C ของ ISO 10816) และความชันเป็นบวกชัดเจน จะคำนวณเวลาที่เหลือก่อนถึง 11 mm/s = (11 − ค่าปัจจุบัน) ÷ ความชัน × ระยะเวลาต่อ sample อยู่ใน `tools/nodered-src/process_machine.js`

**Q: OEE คิดยังไง?**
A: Availability = เวลาเดินเครื่อง ÷ เวลาที่วางแผน, Performance = (Ideal cycle time × จำนวนผลิต) ÷ เวลาเดินเครื่อง, Quality = ของดี ÷ ของทั้งหมด, OEE = A × P × Q มาตรฐานระดับโลก ≥ 85% รีเซ็ตทุกกะ 8 ชั่วโมง

**Q: ทำไมใช้ InfluxDB ไม่ใช้ Google Sheets อย่างเดียว?**
A: ข้อมูลเข้าทุก 2 วินาที × 6 เครื่อง ≈ 260,000 จุด/วัน Sheets มี quota และช้า InfluxDB เป็น time-series DB ที่ query ช่วงเวลาได้เร็ว ส่วน Sheets ใช้เก็บ log สรุปทุก 1 นาทีให้คนอ่าน/แชร์ได้ง่าย

**Q: ทำไมต้องมี Grafana 3 ที่?**
A: แต่ละที่มีผู้ใช้ต่างกัน: Windows = วิศวกรหน้างาน (Engineer dashboard ละเอียด), CasaOS = บน Self-Server ใช้ตอนพัฒนา, Azure = ผู้บริหารดูจากที่ไหนก็ได้ผ่าน Public/Viewer โดยไม่ต้องเปิดฐานข้อมูลในโรงงานสู่อินเทอร์เน็ต (ดึงผ่าน VPN)

**Q: ความปลอดภัย?**
A: InfluxDB ไม่เปิดสู่อินเทอร์เน็ต เข้าได้เฉพาะผ่าน ZeroTier VPN, Telegram รับคำสั่งเฉพาะ chat id ที่อนุญาต, Azure เปิดเฉพาะพอร์ตที่จำเป็นและจำกัด SSH ตาม IP, token ทั้งหมดอยู่ใน `.env` ที่ไม่ขึ้น GitHub, Grafana Public เป็น Viewer อ่านอย่างเดียว

**Q: ถ้า Telegram/Internet ล่ม ข้อมูลหายไหม?**
A: ไม่หาย เพราะ InfluxDB และ Grafana Engineer อยู่ในเครือข่ายโรงงาน (Self-Server) ส่วน Cloud เป็นช่องทางเสริม

**Q: ใช้ AI ตัวไหน ข้อมูลส่งออกไปไหน?**
A: ใช้ API แบบ OpenAI-compatible เปลี่ยนผู้ให้บริการได้ด้วยตัวแปร `AI_BASE_URL` ส่งไปเฉพาะข้อมูลสรุป (ตัวเลข OEE, ค่าสูงสุด, เหตุการณ์) ไม่ส่งข้อมูลดิบ และกำหนด prompt ให้ตอบจากข้อมูลที่ให้เท่านั้น

**Q: ขอดูโค้ดตรงนี้หน่อย / แก้สดได้ไหม?**
A: เปิด VS Code Remote-SSH เข้า Azure แก้ Portal สด หรือแก้ threshold ใน Node-RED แล้วกด Deploy ให้ดู
